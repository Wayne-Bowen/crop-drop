# Test case catalogue

Generated by `node tests/report.js --catalogue`. These are the cases the test runner executes (`npm run test:report`). Every case is run against a clean test database, so results do not depend on earlier runs.

## Login and security

| ID | Type | Test | Steps | Expected result |
|---|---|---|---|---|
| AUTH-01 | Positive | Valid login | POST /api/auth/login with correct credentials | HTTP 200 with the user role |
| AUTH-02 | Negative | Wrong password gives a generic error | Login with a wrong password | HTTP 401 "Incorrect email or password." |
| AUTH-03 | Security | Unknown email gives the same message (no account enumeration) | Login with an email that does not exist | HTTP 401 with the identical message as AUTH-02 |
| SEC-01 | Security | SQL injection in the login email field | Login with email  admin@cropdrop.local' OR '1'='1' --  and any password | HTTP 401, no session created |
| SEC-02 | Security | SQL injection in the password field | Login as a real user with password  ' OR 1=1 -- | HTTP 401 |

| SEC-06 | Security | Password hash is never returned by the API | Inspect the login and /me responses | No password or hash fields |
| SEC-07 | Security | Protected endpoints refuse anonymous requests | Call /api/orders/mine, /api/produce/mine and /api/admin/overview without logging in | All HTTP 401 |

| SEC-09 | Security | CSRF token required for state-changing requests | POST /api/auth/login without the X-CSRF-Token header | HTTP 403 |
| SEC-10 | Security | Logout ends the session | Log in, log out, then request /api/orders/mine | After logout /api/auth/me is empty and orders/mine is HTTP 401 |
| SEC-11 | Security | Session cookie flags | Inspect the Set-Cookie header after login | HttpOnly and SameSite=Lax present (Secure is added in production) |
